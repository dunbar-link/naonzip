# AI 운영실 / DIFM — 1장 요약 (나온집 사례 기반)

> 용도: 소기업·1인기업 대표 대상 1페이지 세일즈. **나온집은 수익/시장 검증 사례가 아니다.**
> "실제로 만들고 운영했다"는 제작·운영 역량 증빙으로만 사용한다.

## 고객 문제

- "아이디어는 있는데 만들 사람이 없다 / 만들어도 운영을 못 한다."
- "외주는 비싸고, 직접 하자니 코드·DB·관리자도구·SEO가 막막하다."
- "어디까지 해도 되는지(저작권·정책) 판단이 어렵다."

## AI가 대신할 수 있는 일

- 공개 페이지 + **관리자 CMS**(입력/검토/게시) 제작
- DB 스키마·권한(RLS)·마이그레이션, 데이터 수집·정규화·중복 방지 파이프라인
- SEO(구조화 데이터·OG·랜딩), 이미지 운영 규칙·스크립트
- "어디서 검증/소개됐는지"(신뢰 출처)를 **사실만** 표시
- 매 단계 타입체크·빌드·실제 노출 검증 + 리포트 문서화

## 사람의 판단이 필요한 일

- 무엇을 만들고 **무엇을 안 만들지** / 방향 전환 결정
- 저작권·개인정보·과장표현 등 **정책 라인의 최종 승인**
- 비즈니스 모델·영업·고객 검증

## 나온집 사례로 증명한 것

- 1인 + AI로 **운영 가능한 풀스택 서비스 + 관리자 CMS + 데이터 파이프라인** 완성
- 신뢰 출처 기능을 **설계부터 실데이터 노출까지** 끝단 검증
- 모든 변경을 작게 쪼개 **검증·문서·롤백 가능**하게 운영
- 규모(참고): 공개 91곳 · 정적 223페이지 · commit 130+개

## 적용 가능한 고객 유형

- 지역 기반 소상공인/큐레이션(맛집·공방·로컬 정보)
- 흩어진 정보를 모아 보여줘야 하는 1인 미디어/협회/소규모 단체
- 내부 운영 도구(입력·검토·게시)가 필요한 소기업

## 패키지 예시

- **A. 운영 도구**: 공개 페이지 + 관리자 CMS + 기본 SEO
- **B. 데이터 정리**: 수집·정규화·중복 제거 + 입력 파이프라인 + 리포트
- **C. 신뢰/출처 표시**: "어디서 소개/검증됐는지" 사실 기반 표시
- **D. 콘텐츠화**: 결과를 case study/블로그/쇼츠로 정리

## 주의 / 한계

- **수익 보장·시장 검증 같은 표현은 쓰지 않는다.** 작게 시작 → 검증 → 확장 원칙.
- 저작권/정책은 고객과 함께 라인을 정하고, 최종 책임·승인은 고객(대표)에게 있다.

## 한 줄 포지셔닝

"AI가 **실행과 운영**을, 대표님이 **판단과 방향**을. 나온집이 그 협업을 실제로 보여줍니다."
