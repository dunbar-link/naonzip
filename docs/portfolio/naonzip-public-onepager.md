# 나온집 — AI로 만든 부산 맛집 큐레이션 (One-pager)

## 한 줄 소개

부산에서 **방송·유튜브·가이드에 나온 맛집을 "출처와 함께" 빠르게 고르는** 모바일 웹 서비스.
기획자 1인이 AI(Claude Code)와 함께 설계·구현·운영·문서화까지 진행했다.

## 무엇을 만들었나

- 공개 서비스: 홈 / 목록 / 상세 / 검색 / 지도 / 저장 + 지역·프로그램·크리에이터·카테고리 랜딩
- 운영자용 Admin CMS: 후보 수집→검토→변환→게시, 편집, 신뢰 출처 관리, 제보 처리
- 데이터 파이프라인: 후보 큐 → 지오코딩 → 비공개 적재 → 공개 게이트 → 공개
- 신뢰 출처 시스템: 방송/유튜브 + 가이드(미쉐린)·로컬(비짓부산) 등 "어디서 봤는지"를 칩·링크로 표시
- 규모: 공개 식당 91곳 / 정적 223페이지 / commit 129개

## AI가 한 일

- 데이터 후보 수집(공개 웹 검색 수준), DB 스키마·RLS·마이그레이션 설계
- UI 컴포넌트, Admin CMS server action, SEO 구조(JSON-LD/OG/ISR), 이미지 운영 스크립트
- 신뢰 출처 구조 설계·입력 UI·표시·후보 리포트·안전 import
- 매 단계 tsc/build·프리렌더 검증과 리포트 문서화

## 사람이 한 일

- 문제 정의와 우선순위, 방향 전환(사업화 → 포트폴리오) 판단, 최종 승인
- 저작권/정책 기준 결정, "무엇을 하지 않을지"(예약·광고·전국확장) 선택

## 기술 스택

Next.js 16 App Router · React 19 · Tailwind CSS v4 · TypeScript · Supabase(Postgres + RLS) ·
Kakao Map · Vercel(ISR)

## 주요 기능

- 상세페이지: 핵심정보 + 출처 칩 + CTA(지도/전화/공유) + "어디서 봤나요" + "추가 출처(신뢰 출처)"
- Admin: 후보 변환·게시 워크플로, 신뢰 출처 CRUD, 제보 큐, 붙여넣기 빠른 등록
- SEO: 구조화 데이터·동적 OG 이미지·랜딩 페이지·sitemap

## 성과

- 운영 가능한 작은 풀스택 서비스 + CMS + 데이터 파이프라인을 실제로 완성
- 신뢰 출처가 설계→입력→표시→링크→실데이터까지 끝단 동작
- 감사 추적 가능한 Phase 단위 문서/리포트

## 한계 (솔직하게)

- 예약/웨이팅 기능 없음, 식당 대상 수익모델 약함
- 실제 트래픽·수익은 검증하지 않음
- 이미지·출처 저작권은 지속적인 정책 관리가 필요
- 신뢰 출처 데이터는 아직 소량(운영자 수동 확장 필요)

## 포트폴리오 가치

"AI로 실제 서비스를 **어디까지 만들고 운영할 수 있는가**"를 보여주는 구체 사례.
사람은 판단/방향, AI는 실행/검증/문서를 맡는 협업 방식을 그대로 드러낸다.

## 한 줄 결론

큰돈을 번 서비스는 아니다. 하지만 **1인 + AI로 실제 운영 가능한 서비스와 운영 체계를 만들 수
있다는 것**을 증명한 사례다.
