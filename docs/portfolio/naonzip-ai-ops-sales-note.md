# AI 운영실 / DIFM 영업 메모 (나온집 사례 기반)

> 용도: 소기업·1인기업 대표에게 "AI가 대신 해줄 수 있는 운영 범위"를 설명할 때 쓰는 내부 메모.
> **주의: 나온집은 수익/시장 검증 사례가 아니다.** "실제로 만들고 운영했다"는 제작·운영 역량 증빙으로만 사용한다.

## 1. 고객에게 보여줄 수 있는 메시지

- "아이디어만 있으면, **실제 돌아가는 작은 서비스 + 운영 도구**까지 만들 수 있습니다."
- "대표님은 **판단과 방향**만, 나머지 **실행·검증·문서화는 AI가** 합니다."
- "화려한 데모가 아니라, 데이터·관리자도구·SEO까지 **운영이 도는** 형태로 드립니다."
- "무리한 확장은 안 합니다. **하지 말 것을 같이 정하는 것**도 서비스의 일부입니다."

## 2. AI가 대신 해줄 수 있는 것 (나온집에서 실제로 한 일)

- 데이터 후보 수집·정리(공개 정보 범위)와 입력 파이프라인
- DB 스키마·권한(RLS)·마이그레이션 설계
- 사용자 화면(모바일 웹) + 관리자 CMS 구현
- SEO(구조화 데이터·OG 이미지·랜딩 페이지)
- 이미지 운영 규칙·스크립트(저작권 안전 원칙 포함)
- 신뢰 출처(어디서 봤는지) 구조 설계·입력 도구·표시
- 매 단계 타입체크·빌드·실제 화면 노출 검증 + 리포트 문서화

## 3. 대표가 직접 하지 않아도 되는 것

- 코드/DB 설계, 관리자 도구 제작, 반복 검증, 배포 준비
- 데이터 입력 양식·중복 방지·게시 게이트 같은 운영 잡일의 자동화
- "이거 어디까지 안전하게 해도 되나"의 1차 정리(법적/저작권 리스크 플래그)

## 4. 대표가 반드시 해야 하는 것 (AI가 대신 못 함)

- 무엇을 만들고 **무엇을 안 만들지**의 판단
- 방향 전환 결정(예: 사업화 → 포트폴리오)
- 저작권·개인정보·과장표현 등 **정책 라인의 최종 승인**
- 실제 비즈니스 모델·영업·고객 검증

## 5. 나온집 사례에서 증명된 것

- 1인 + AI로 **운영 가능한 풀스택 서비스 + 관리자 CMS + 데이터 파이프라인**을 완성
- 신뢰 출처 기능을 설계부터 실데이터 노출까지 **끝단**으로 검증
- 모든 변경을 작은 단위로 쪼개 **검증·문서·롤백 가능**하게 운영
- 규모(참고): 공개 91곳 / 정적 223페이지 / commit 129개

## 6. 제안 가능한 서비스 패키지 예시 (소기업/1인기업)

- **A. 운영 도구 패키지**: 간단한 공개 페이지 + 관리자 CMS(입력/검토/게시) + 기본 SEO
- **B. 데이터 정리 패키지**: 흩어진 정보 수집·정규화·중복 제거 + 입력 파이프라인 + 리포트
- **C. 신뢰/출처 패키지**: "어디서 검증/소개됐는지"를 안전하게 표시(과장 없이 사실만)
- **D. 콘텐츠화 패키지**: 만든 결과를 case study/블로그/쇼츠 소재로 정리

> 각 패키지는 "작게 시작 → 검증 → 확장" 원칙. **수익 보장·시장 검증 같은 표현은 쓰지 않는다.**

## 7. 한 줄 포지셔닝

"AI가 **실행과 운영**을, 대표님이 **판단과 방향**을. 나온집이 그 협업을 실제로 보여줍니다."
