# 나온집 검색 사용성 테스트 가이드 (진행자용)

> 이 문서는 테스트를 **진행하는 사람**이 보는 문서다.
> 사용자(테스터)에게는 보여주지 않는다.

---

## 0. 이 테스트의 성격 (먼저 읽기)

- 현재 검색 UI는 **이미 구현 완료** 상태다.
- 이번 단계는 **기능 개발이 아니라 실사용 검증**이다.
- 테스트에서 나온 새 아이디어를 **바로 개발하지 않는다.**
- **같은 문제가 2명 이상에게 반복될 때만** 수정을 검토한다.
- 사용자가 **성공한 행동도 반드시 기록**한다.
- 진행자는 **사용법을 먼저 설명하지 않는다.**

---

## 1. 테스트 목적

이번 테스트에서 확인할 것은 4가지뿐이다.

1. 사용자가 검색 필터를 **설명 없이 발견**하는가
2. **미슐랭·부산공식** 필터의 의미를 이해하는가
3. **검색어와 필터를 함께** 사용할 수 있는가
4. 원하는 식당 **상세 페이지까지 자연스럽게** 들어가는가

> 디자인 취향 조사나 신규 기능 아이디어 수집이 **아니다.**

---

## 2. 테스트 대상

- 총 **3~5명**
- 나온집 개발에 참여하지 않은 사람
- **스마트폰**으로 테스트
- 가능하면 연령대가 다른 사용자 포함
- 테스트 전 기능 설명 **금지**
- 사용자가 막혀도 **10초 동안 먼저 지켜본 뒤** 최소한의 도움만 제공

개인정보는 수집하지 않는다. 이름은 익명으로 기록한다.

- Tester 01 / Tester 02 / Tester 03 ...

---

## 3. 진행 순서

1. 테스터 스마트폰에서 검색 페이지를 연다 → <https://naonzip.vercel.app/search>
2. 이 정도만 안내: "이제부터 몇 가지를 직접 찾아보실 거예요. 정답은 없고, 평소처럼 편하게 써보시면 돼요."
3. **과제 1 → 과제 2 → 과제 3** 순서로 문구를 읽어준다
4. 각 과제마다 관찰 항목을 보고 [피드백 로그](search-usability-feedback-log.md)에 기록
5. 3개 과제가 끝나면 **질문 5개**를 묻는다
6. 다음 테스터로 넘어간다

> 진행자는 옆에서 **조용히 관찰**한다. 힌트를 먼저 주지 않는다.

---

## 4. 사용자에게 읽어줄 과제 문구

> 아래 따옴표 문구만 그대로 읽어준다. **추가 설명 금지.**

### 과제 1 — 미슐랭 식당 찾기

읽어줄 문구:

> "부산의 미슐랭 식당을 찾아보세요."

관찰 항목:
- 미슐랭 필터를 바로 찾는지
- 추천 검색어를 누르는지
- 직접 검색어를 입력하는지
- 결과 수를 이해하는지
- 식당 상세 페이지까지 들어가는지

성공 기준:
- 설명 없이 **10초 안에** 미슐랭 결과 화면 진입
- 식당 하나의 **상세 페이지까지** 진입

### 과제 2 — 부산공식 국밥집 찾기

읽어줄 문구:

> "부산에서 공식적으로 소개된 국밥집을 찾아보세요."

관찰 항목:
- 부산공식 필터 의미를 이해하는지
- 국밥 검색어와 부산공식 필터를 함께 적용하는지
- 현재 선택된 필터를 인지하는지
- 결과가 적어도 오류로 오해하지 않는지

성공 기준:
- 검색어와 부산공식 필터를 **함께 적용**
- 결과 식당 하나를 선택

### 과제 3 — 가고 싶은 식당 찾기

읽어줄 문구:

> "본인이 실제로 가보고 싶은 식당 하나를 찾아보세요."

관찰 항목:
- 검색창·추천 검색어·필터 중 어떤 경로를 쓰는지
- 검색 결과 카드 정보를 이해하는지
- 상세 페이지에서 이미지·주소·지도·출처를 확인하는지
- 최종 선택 이유

성공 기준:
- 도움 없이 식당 하나 선택
- 선택 이유를 한 문장으로 설명 가능

---

## 5. 관찰 방법

각 과제마다 아래를 본다. (자세한 기록은 [피드백 로그](search-usability-feedback-log.md))

- 첫 클릭/터치 위치
- 막힌 위치
- 도움을 줬는지 여부
- 사용자가 **실제로 말한 표현** (그대로 받아적기)
- 성공/실패
- 완료까지 걸린 시간

> 사용자가 막혀도 **10초는 지켜본다.** 그 다음에도 못 하면 최소한의 힌트만.

---

## 6. 테스트 후 질문 5개

3개 과제가 끝난 뒤 아래 5개만 묻는다. (길게 유도하지 않기)

1. 처음 화면에서 무엇을 할 수 있는지 바로 알았나요?
2. 미슐랭과 부산공식 필터가 눈에 잘 보였나요?
3. 부산공식이라는 말의 뜻을 이해했나요?
4. 검색하면서 불편하거나 헷갈린 부분이 있었나요?
5. 실제로 다시 사용할 이유가 있나요?

---

## 7. 성공 판정 기준

### 전체 PASS 기준
- 테스트 인원 **3명 이상**
- 과제 1 성공률 **80% 이상**
- 과제 2 성공률 **60% 이상**
- 과제 3 성공률 **80% 이상**
- **P0 0건**
- 동일 P1 반복 **1개 이하**
- 사용자 **절반 이상**이 다시 사용할 이유를 설명

### 테스터가 3명일 때 환산
- 과제 1: 3명 중 **2명** 성공
- 과제 2: 3명 중 **2명** 성공
- 과제 3: 3명 중 **2명** 성공

> 숫자를 억지로 좋게 해석하지 않는다.

---

## 8. 문제 분류 기준 (기록 시 severity)

| 등급 | 기준 |
|---|---|
| **P0** | 검색 자체 불가 / 페이지 깨짐 / 필터 미작동 |
| **P1** | 2명 이상 같은 지점에서 막힘 · 미슐랭·부산공식 필터 발견 실패 · 모바일 키보드 때문에 진행 곤란 · 검색결과·선택필터 이해 못함 |
| **P2** | 1명만 불편 · 문구·간격 경미한 개선 · 기능엔 지장 없음 |
| **Backlog** | 신규 기능 제안 · 개인 취향 · 현재 검색 목표와 무관한 의견 |

### 개발 시작 조건
- **P0** → 즉시 검토
- **P1** → 같은 문제가 **2명 이상 반복될 때만** 수정
- **P2 / Backlog** → 이번 회차에서는 개발하지 않음

---

## 9. 테스트 중 설명 금지 원칙 (꼭 지키기)

- 진행자가 **사용법을 먼저 설명하지 않는다.**
- "미슐랭 필터는 여기 있어요" 같은 힌트 금지.
- 사용자가 막혀도 **10초는 지켜본다.**
- 도움을 줬다면 로그에 **반드시 기록**한다 (help_needed = Y).
- 성공한 행동도 **빠짐없이 기록**한다.
