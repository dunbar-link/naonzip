# 검색 사용성 테스트 — 대장용 진행 체크리스트

> 스마트폰 보면서 그대로 진행하는 한 장짜리 표.
> 자세한 진행은 [테스트 가이드](search-usability-test-guide.md), 기록은 [피드백 로그](search-usability-feedback-log.md).

> 이번 회차는 **실사용 검증만** 한다. 기능 개발·UI 수정·신규 기능 추가는 **하지 않는다.**

---

## ✅ 테스트 전 준비

- [ ] 테스터 3~5명 섭외 (개발 미참여, 가능하면 연령대 다양)
- [ ] 각자 스마트폰 준비
- [ ] 검색 페이지 미리 열어두기
- [ ] 피드백 로그 파일 열어두기
- [ ] **기능 설명 안 하기** 마음먹기

---

## 🔗 테스트 링크

```text
https://naonzip.vercel.app/search
```

---

## 🗣️ 과제 문구 (이 3개만 읽어주기)

```text
과제 1: "부산의 미슐랭 식당을 찾아보세요."
과제 2: "부산에서 공식적으로 소개된 국밥집을 찾아보세요."
과제 3: "본인이 실제로 가보고 싶은 식당 하나를 찾아보세요."
```

> 문구만 읽어준다. 추가 설명·힌트 금지.

---

## 👀 테스트 중 체크 (과제마다)

- [ ] 첫 터치 위치 봤다
- [ ] 막힌 곳 봤다
- [ ] 막혀도 **10초 기다렸다**
- [ ] 도움 줬으면 기록했다 (help_needed = Y)
- [ ] 사용자가 한 말 그대로 받아적었다
- [ ] **성공도 기록**했다

> 힌트 먼저 주지 않기. 조용히 관찰.

---

## ❓ 테스트 후 질문 (5개)

```text
1. 처음 화면에서 뭘 할 수 있는지 바로 알았나요?
2. 미슐랭·부산공식 필터가 눈에 잘 보였나요?
3. 부산공식이라는 말 뜻을 이해했나요?
4. 불편하거나 헷갈린 부분 있었나요?
5. 실제로 다시 쓸 이유가 있나요?
```

---

## 📋 결과 복붙 위치

- 과제별 기록 → [피드백 로그](search-usability-feedback-log.md) "기록 표"
- 질문 답변 → 피드백 로그 "테스트 후 질문 답변 기록" 표
- 집계 → 피드백 로그 "집계" 블록
- 최종 결과는 **이 채팅에 그대로 복붙** → 반복된 P0/P1만 수정 판단

---

## 🎯 테스트 완료 조건

- [ ] 3명 이상 테스트 완료
- [ ] 과제별 성공/실패 다 기록
- [ ] 질문 5개 답변 다 받음
- [ ] P0/P1 정리됨
- [ ] 집계 표 채움

### PASS 기준 (요약)

```text
인원 3명 이상
과제1 성공 80%↑ (3명이면 2명)
과제2 성공 60%↑ (3명이면 2명)
과제3 성공 80%↑ (3명이면 2명)
P0 0건
동일 P1 반복 1개 이하
절반 이상 "다시 쓸 이유" 설명
```

> 신규 기능 개발은 보류. 동일 문제가 **2명 이상 반복**될 때만 수정 검토.
